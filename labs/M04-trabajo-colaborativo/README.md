# M04 — Trabajo colaborativo en GitLab

[← Página anterior](../M03-ramas-y-conflictos/README.md) · [Siguiente página →](00-roles-issues-y-mr.md)

El manual lo mantiene un equipo, no una persona. En parejas, compartís un proyecto: cada cambio nace en una issue, se propone en una merge request y lo revisa el compañero antes de entrar en una rama principal protegida.

## Qué aprenderás

- Miembros del proyecto y roles básicos
- Issues para registrar tareas e incidencias
- Merge requests: creación, revisión y fusión
- Comentarios y sugerencias de cambio
- Cómo se relacionan issues, ramas y merge requests
- Proteger la rama principal
